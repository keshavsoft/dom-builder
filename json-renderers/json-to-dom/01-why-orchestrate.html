One UI. Three Construction Paradigms.

To understand why KeshavSoft built a dedicated DOM orchestrator, we must look at how UI has traditionally been constructed — and where imperative approaches fail at enterprise scale.

1 · Approach 1: Original HTML Markup

Writing raw HTML strings directly into templates: 

<div id="test-content">
  <label>Name</label>
  <p>Test Content</p>
</div>

Test Content

The Limitation: Static markup works for brochures, but modern enterprise UIs are data-driven. Constructing complex markup via string interpolation invites catastrophic Cross-Site Scripting (XSS) vulnerabilities.

2 · Approach 2: Vanilla JavaScript (Imperative DOM)

Creating each node imperatively using browser DOM APIs: 

const div = document.createElement("div");
div.id = "test-content";

const label = document.createElement("label");
label.textContent = "Name";

const text = document.createElement("p");
text.textContent = "Test Content";

div.append(label, text);
document.getElementById("container").replaceChildren(div);

The Pain: 10x code bloat. Building a 20-row table with badges and action buttons requires hundreds of repetitive, error-prone createElement commands that cannot be serialized or transferred over an API.

3 · Approach 3: The Declarative Specification

Model the intended structure as serializable JSON data: 

{
  "tagName": "div",
  "attributes": { "id": "test-content" },
  "children": [
    { "tagName": "label", "textContent": "Name" },
    { "tagName": "p", "textContent": "Test Content" }
  ]
}
The Breakthrough: By separating what to build (JSON data) from how to build it (compiler engines), our UI becomes portable data. Now we need an engine to synthesize that JSON into DOM — and another to mount it.
