The Architectural Orchestrator

@keshavsoft/json-to-dom is not a monolithic script — it is an orchestrator. It delegates DOM synthesis and mounting to two specialized, battle-tested sibling repositories: @keshavsoft/json-to-tag (the tag compilation engine) and spec-to-dom (the target element mounting engine).

The Two Delegated Engines

How the two sibling repositories divide the work

Instead of coupling tag validation, element creation, and DOM mounting into a heavy single package, @keshavsoft/json-to-dom cleanly splits responsibilities between two focused engines:

Engine 01 · Synthesis

@keshavsoft/json-to-tag

The W3C grammar compiler. It inspects every element in your specification tree and instantiates real DOM nodes safely.

  • Validates element tag names against HTML standards (void vs container).
  • Recursively converts nested children without risky innerHTML.
  • Applies classes, properties, and standard attributes safely.
  • Outputs a ready-to-mount buildSpec element or DocumentFragment.
Engine 02 · Mounting

spec-to-dom

The DOM target mount specialist. It handles all mechanics related to the live webpage container.

  • Resolves target HTML elements via document.getElementById(targetHtmlId).
  • Differentiates between single element nodes and node collections.
  • Supports flexible mounting modes: prepend, append, or clean container reset.
  • Returns the live, mounted DOM container back to the caller.
Source Code Truth

The complete orchestration logic in 12 lines

This is the actual production orchestrator from json-to-dom/src/v42/index.js: 

import registerGlobal from "./register/index.js";
import jsonToTag from "@keshavsoft/json-to-tag"; // Engine 1: Synthesis
import specToDom from "spec-to-dom";             // Engine 2: Mounting

const startFunc = ({ jsonSpec, targetHtmlId, appendPosition, showLog }) => {

    // 1. Hand off to @keshavsoft/json-to-tag: parse spec & synthesize DOM nodes
    const buildSpec = jsonToTag(jsonSpec);

    // 2. Hand off to spec-to-dom: resolve target container & mount
    const container = specToDom({ buildSpec, targetHtmlId, appendPosition, showLog });

    return container;
};

registerGlobal(startFunc);

export default startFunc;
Why this design wins: If you need headless tag synthesis on a server (SSR with jsdom), you use @keshavsoft/json-to-tag alone. If you already have elements and just need robust container mounting, you use spec-to-dom alone. @keshavsoft/json-to-dom provides the unified browser experience.
