Step 03 of 04

Model UI as a declarative JSON tree.

Instead of writing imperative commands, @keshavsoft/json-to-dom represents components as pure, serializable JSON specifications that any environment can generate, send, or store.

1 · The JSON Specification

Standard serializable JSON object describing structure and hierarchy: 

{
  "tagName": "div",
  "attributes": { "id": "test-content" },
  "children": [
    { "tagName": "label", "textContent": "Name" },
    { "tagName": "p", "textContent": "Test Content" }
  ]
}

2 · Key Specification Fields

Every specification node uses simple, standardized keys:

01 · Element

tagName

The native HTML tag to instantiate (e.g. "div", "label", "table", "button").

02 · Attributes

attributes

Key-value map of HTML attributes like id, class, type, or colspan.

03 · Children

children

An array of nested specifications. Each child is processed recursively using the exact same contract.

The Architectural Shift: UI as Data

Decoupled from Frameworks: Instead of coupling your UI structure to client-side templates or heavy JSX compilers, your UI is now valid, standard JSON. It can be sent over HTTP APIs, generated dynamically on backend servers, stored in databases, or loaded from flat configuration files.
