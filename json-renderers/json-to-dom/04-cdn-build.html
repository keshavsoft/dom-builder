Chapter 04 of 04

Live End-to-End Orchestration via CDN.

See how @keshavsoft/json-to-dom brings @keshavsoft/json-to-tag and spec-to-dom together in a single browser import.

1 · Complete Working Example

A standalone HTML file that imports the orchestrator and renders into a live target container: 

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>json-to-dom Orchestration Demo</title>
</head>
<body>
  <!-- 1. Target container element in your document -->
  <div id="my-container"></div>

  <script type="module">
    // 2. Import the orchestrator via CDN
    import jsonToDom from "https://cdn.jsdelivr.net/npm/@keshavsoft/json-to-dom/+esm";

    // 3. Define the UI specification (from json-renderers-build or backend)
    const spec = {
      tagName: "div",
      attributes: { id: "test-content", class: "card-body" },
      children: [
        { tagName: "label", textContent: "Name" },
        { tagName: "p", textContent: "Test Content" }
      ]
    };

    // 4. One call triggers the two-engine pipeline:
    //    -> jsonToTag(spec) synthesizes native DOM nodes
    //    -> specToDom(...) mounts into "my-container"
    jsonToDom({
      jsonSpec: spec,
      targetHtmlId: "my-container",
      appendPosition: "beforeend"
    });
  </script>
</body>
</html>

2 · What Happened Behind the Scenes

Zero boilerplate, zero innerHTML risks: @keshavsoft/json-to-dom cleanly coordinated the pipeline:
• Engine 1 checked W3C tags, created native HTMLDivElement, HTMLLabelElement, and HTMLParagraphElement instances with zero unsafe string interpolation.
• Engine 2 located #my-container, cleared old contents, and attached the compiled nodes into the active DOM tree.
