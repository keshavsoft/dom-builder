json-to-tag Developer Guide

Master the two execution modes of json-to-tag: blazing-fast production rendering with buildSpecElement, and diagnostic debugging with buildSpecElementWithValidate.

Execution Modes

Choosing the Right Function

In modern web development, validation is crucial during development and testing, but can be pure overhead during 60 FPS animation loops or large batch table renders. json-to-tag provides two specialized functions to give you the best of both worlds:

Feature buildSpecElement (Classic) buildSpecElementWithValidate (Guard)
Primary Purpose Production builds, pre-compiled specs, animation loops Development, interactive playgrounds, user-supplied JSON
Performance Overhead 0.00% (Zero validation overhead) Pre-flight structural tree scan
Diagnostic Logging Silent — compiles directly Warns in console.warn with exact invalid node paths
Mechanism traverse({ inSpec, inFunc: buildElement }) Runs validate() first, then runs traverse()
Code Walkthrough

Usage Examples

1. High-Speed Production Mode

import { buildSpecElement } from "@keshavsoft/json-to-tag";

// Flexible signature: accepts { spec }, { inSpec }, or direct object
const button = buildSpecElement({
  spec: {
    tagName: "button",
    classList: "btn btn-primary",
    textContent: "Save Changes",
    attributes: { type: "submit" }
  }
});

document.body.appendChild(button);

2. Development Mode with Validation Warning

import { buildSpecElementWithValidate } from "@keshavsoft/json-to-tag";

// If a specification has a schema mistake (e.g. invalid tag or key):
const badSpec = {
  tagName: "btn-custom", // unrecognized or malformed
  children: [{ invalidProperty: 123 }]
};

// Will log a diagnostic warning in the DevTools console, then continue compiling:
const element = buildSpecElementWithValidate({ spec: badSpec });
// Console Output:
// [json-to-tag] Specification validation issues: [
//   { path: "root", message: "Unknown tag 'btn-custom'" }
// ]
Data Contract

JSON Specification Schema

Every element specification is a serializable plain JSON object supporting the following standard fields:

Field Type Compulsory? Description
tagName string Yes W3C HTML tag name (e.g. "div", "table", "button")
textContent string No Text inside the element (assigned via element.textContent)
classList string No Space-separated CSS class names (e.g. "btn btn-primary shadow")
attributes object No HTML attributes and datasets (e.g. { type: "button", "data-id": "42" })
properties object No Direct DOM object properties (e.g. { checked: true, disabled: false })
children array No Recursive list of child element specifications or string nodes
CDN & Vanilla JS

Global Browser Namespace

When imported directly via CDN or script tag in non-module environments, json-to-tag attaches itself cleanly to the standard KeshavSoft namespace: 

// Available on window.ks:
window.ks['json-to-tag'].buildSpecElement(spec);
window.ks['json-to-tag'].buildSpecElementWithValidate(spec);
