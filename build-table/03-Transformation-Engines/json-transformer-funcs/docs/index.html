THE ORCHESTRATOR

JSON Transformer Funcs

A coordinated set of three JSON-to-JSON transformation engines, each responsible for a different shape of output.

The overall story

The system turns JSON descriptions and data into JSON element trees. It does not create browser DOM nodes itself. The resulting tree can be consumed by a renderer or another stage.

What the orchestrator contributes

The package entry point re-exports the three engines and also exposes resolvePath and findByRole. The repository's samples express a build as a sequence: resolve source data, call the selected transformation with a template, then place the result at a destination in the base structure.

The important distinction is that the engines perform transformations; the sample runner coordinates them. The base structure supplies the surrounding container, while the spec supplies reusable templates.

Alignment checks from this source snapshot

The architecture roles are distinct in the active entry points. One packaging detail does not align in the uploaded snapshot: the orchestrator declares json-transformer-funcs-one-dimension as ^1.5.2, while the sibling repository's package metadata says 1.5.1. A local sibling source folder does not automatically become the installed npm dependency. Publish/install versions must be reconciled before claiming the four packages are release-aligned.

The other declared ranges are json-transformer-funcs-primitive ^1.9.1 and json-transformer-funcs-two-dimensions ^1.5.2; the uploaded sibling metadata is primitive 1.9.2 and two-dimensional 1.6.1. Those satisfy the stated ranges. This page explains responsibilities; it does not claim that every release or sample has passed integration testing.

Reading the contracts

  • data contains values and collections.
  • spec names templates such as header, row, and cell shapes.
  • base describes the structural skeleton that receives generated nodes.
  • Instructions connect source paths, engine functions, template keys, and destination paths.

These are the intended roles documented by the samples. The public package exports and the active source files remain the authority when a legacy document describes an older version.
