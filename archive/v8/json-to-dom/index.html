Architecture

How the Two Engines Coordinate

Instead of coupling element creation and container mounting into a monolithic library, json-to-dom orchestrates them cleanly in two clear steps:

JSON Specification (Data Contract) │ ▼ ┌─────────────────────────────────────────────────────────┐ │ @keshavsoft/json-to-dom │ │ │ │ 1. jsonToTag(jsonSpec) │ │ └──► @keshavsoft/json-to-tag │ │ (Step 1: W3C Node Synthesis & Validation) │ │ │ │ 2. specToDom({ buildSpec, targetHtmlId, ... }) │ │ └──► spec-to-dom │ │ (Step 2: Container Resolution & Safe Mount) │ └─────────────────────────────────────────────────────────┘ │ ▼ Native Browser DOM Tree
The Natural Execution Order: First json-to-tag synthesizes the native DOM elements in memory. Next spec-to-dom resolves the destination HTML container and mounts the elements cleanly.
Master API

One-Line Invocation

import jsonToDom from "@keshavsoft/json-to-dom";

jsonToDom({
  jsonSpec: {
    tagName: "div",
    classList: "card shadow-sm p-4",
    children: [
      { tagName: "h3", textContent: "User Account" },
      { tagName: "p", textContent: "Rendered dynamically without Virtual DOM." }
    ]
  },
  targetHtmlId: "app"
});
